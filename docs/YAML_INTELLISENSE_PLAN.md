# YAML IntelliSense強化：実装計画

## 範囲

既存Ace Editorを維持し、補完・診断をDOM非依存のモジュールへ分離する。
ソルバー、既定値、保存／実行API、保存済みベンチのバイナリやハーネスは変更しない。
エラー表示は編集支援であり、入力の自動修正や新たな実行禁止は行わない。

## 今回の実装順序

1. パスを区別する補完・検証を新設する。既存辞書の同名キー衝突
   （mesh.dxとslides.dx、境界alphaとEW.alphaなど）を文脈別の定義で補う。
   既知キーでも不適切な階層では警告する。未知項目は警告止まりとする。
2. コイル材料名を解析YAMLのmaterialsから補完し、未定義参照を警告する。
   材料ライブラリはサーバでpresetに変換されるため、その名前をコイル断面と混同しない。
   片側material_aまたはmaterial_bだけの定義を許容する。
3. 実際のYAML解析結果で型・選択肢・設定間の関係を検証する。
   数式／$変数の評価をJavaScriptで再実装しない。未評価の式は大小比較を省略する。
   半径範囲、EW上下限、Andersonのdepth/betaを重点対象にする。
4. Aceの補完・行診断へ接続する。入力中の未完成YAMLを考慮する。
   構文エラーはパーサのmarkを使い、行と列を正しく表示する。
5. Nodeテストにより階層、配列、引用符、コメント、ブロック文字列、
   数式、未知材料、片側コイル、型、境界値、UI接続を検証する。
   既存のプロセスライフサイクル試験も継続実行する。

## 受入条件と限界

- 補完候補／説明が現在の階層に一致し、キー名を材料名と誤認しない。
- 型は既存C++のスカラー変換と数式処理を考慮する。
- 材料名由来のHTMLをエスケープする。入力文字列を実行しない。
- インラインYAML等の高度な編集位置で安全に補完できない場合は候補を控える。
  検証自体は正しくパースされた木を使用する。
- 研究用のjacobian等を既定の補完候補へ公開しないが、配置が正しければ未知扱いしない。
- 今回は解析設定エディターが対象。材料ライブラリエディターの全面刷新、
  標準JSON Schema、VS Code統合、MCPは次段階。
- 着手時は長時間の全周ベンチを保留。後日（2026-10-15）の完了結果・次回手順はTODO_NEXT_STEPS.mdを参照。

## 将来の拡張

公開仕様のパス別定義を標準JSON Schemaへ整理し、UI／CLI／MCPの検証契約を共通化する。
その際も数式・外部ライブラリ・実験設定を別扱いにし、ソルバー入力との適合試験を維持する。

## 初回実装結果（2026-10-13）

- `webui/public/yaml-intellisense.js` を追加し、解析設定エディターから使用するよう変更。
  パス別の候補・説明、ローカル材料名の補完、型／列挙値／配置先の診断、
  半径・EW上下限・Andersonの値チェックを実装した。
- 同名キーは文脈別に定義を補正。ライブラリ由来presetをコイル断面名として提案しない。
  片側コイルと数式・変数置換を維持。既存のブロックスニペットはキー位置で維持する。
- 診断はパース済みYAMLを対象とする。ブロック記法の行位置は独立したロケーターで求める。
  フロー記法の個別キー位置が取れない場合は親ブロックの行を使用する。
  引用符内・コメント内等の不確かなカーソル位置では補完を控える。
- 既存辞書は標準JSON Schemaではない。今回、すべての入力仕様を網羅したとは扱わない。
  未評価の式の大小関係、外部ファイルの存在、B-Hテーブルの物理的妥当性は検証対象外。
- 新規22件（実際のAce接続関数のスタブ試験を含む）と既存12件、合計34件が
  `npm --prefix webui test` で合格。JavaScript構文チェックも合格。
  同梱sample_configと2件のベンチ設定で誤警告がないことを確認した。
- 実ブラウザでの候補ポップアップ表示・キーボード挿入操作は未検証。
  次回はその操作確認、説明文の残りの整理、ライブラリエディターとの共通化を検討する。
- ソルバーの実装、ビルド済みバイナリ、長時間ベンチには変更なし。
  初回時点では未コミット。2026-10-15にUI／MCPとの統合後68件の再試験を通し、成果をまとめて記録。
