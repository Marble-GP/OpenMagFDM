# Reproducible solver experiments

Run from the repository root. Keep baseline and trial builds separate and do
not benchmark concurrently with compilation, another solver or intensive work.
The full protocol and negative historical results are in
[`docs/research/SOLVER_SPEED_CONVERGENCE.md`](../../docs/research/SOLVER_SPEED_CONVERGENCE.md).

## Small numerical cases

The repository-contained fixtures are generated by `solver_numerics_test` and
`chunk_threads_test`: no external model image is needed. They cover independent
legacy assembly comparisons, residuals, material derivatives, Jv, AA rollback,
FGMRES candidates and actual OpenMP chunk allocation.

```text
cmake --build build --config Release
ctest --test-dir build -C Release --output-on-failure
python -m pip install -r benchmarks/solver_speed/requirements.txt
python -m unittest discover -s benchmarks/solver_speed -p "test_*.py"
```

On Windows also run `tests/release_contract_smoke.ps1 -PackageDir <package>`
against a solver package containing its dependencies and general materials.

## Timing the primary case

`ieej_12step.yaml` expects the 450 x 2976 IEEJ-D polar PNG. The large user model
is not redistributed here; the harness records its SHA256 and absolute path.
The YAML fixes 12 steps, 12-pixel motion, chunks=1, tolerance=1e-3 and max=300.
Use the same PNG and YAML for both phase-1 binaries, with no YAML thread override.

```text
python benchmarks/solver_speed/run_comparison.py --baseline <baseline-exe> --trial <trial-exe> --baseline-repo <baseline-worktree> --trial-repo . --config benchmarks/solver_speed/ieej_12step.yaml --image <polar-png> --output <new-results-directory> --threads 12 --repeats 3
```

Repeats alternate baseline, trial. The manifest captures source, configuration,
executable/dependency hashes and toolchain; measurements include process exit,
output completion and memory. Exit 2/unconverged steps invalidate speed claims.
The script does not perform waveform validation or automatically adopt a change.

`--stop-after-runs 1` pauses **after** one new completed measurement. Continue
with the same arguments plus `--resume`; unchanged input/binary hashes are
required. Incomplete run directories remain intact and retries get new names.
Do not reuse a completed run after changing the executable or input.

For phase 2, use optimized secant as baseline and a separate YAML with only
`nonlinear_solver.jacobian: tangent` changed as `--trial-config <yaml>`.
Compare candidates sequentially with `--trial-preconditioner secant-amg`,
`tangent-amg`, then `tangent-ilut`, each in a new output directory. No broad
parameter search is intended. The default solver remains secant.

Before committing to long sweeps, `run_tangent_screen.py` runs a sequential
one-step cold-start diagnostic with the same executable: secant, then A/B/C.
Pass `--exe <tangent-build-exe> --repo . --config <12-step-yaml> --image <png>
--output <new-directory> --threads 12`. It preserves max iterations/tolerance
and physical settings, changing only the number of steps and Jacobian option.
Each child has a 600-second diagnostic time limit and an 8-GiB memory guard.
Terminated or unconverged runs are not speed comparisons. `--resume` reuses
completed diagnostics with matching hashes; incomplete directories are retained.
The summary records inner iterations, tangent acceptance and secant fallback
counts. This screening does not replace the paired 12-step adoption protocol.
Use `--candidates tangent-amg --trial-objective energy` for the bounded extra
energy-merit comparison. The secant control retains the source YAML's settings;
only the tangent candidate's merit changes. Manifest/resume checks include the
candidate list and merit. The default list remains A/B/C with residual merit.

## Priority-4 paired screen

`run_field_reuse_pairs.py` uses the completed idle retest's manifest to pin
the trial executable, DLLs, configuration and image. It compares masks 6
(priorities 2+3) and 14 (2+3+4), with priority 1 off, in AB/BA/AB order.
No rebuild, solver/default changes or simultaneous children are involved.

```text
python benchmarks/solver_speed/run_field_reuse_pairs.py --prior-manifest ../bench_results/workspace_idle_retest_20261008_01/manifest.json --output ../bench_results/workspace_field_reuse_20261009_01 --prepare-only
python benchmarks/solver_speed/run_field_reuse_pairs.py --prior-manifest ../bench_results/workspace_idle_retest_20261008_01/manifest.json --output ../bench_results/workspace_field_reuse_20261009_01 --resume
python -m unittest discover -s benchmarks/solver_speed -p test_field_reuse_pairs.py
```

The first command validates/records without starting computation. Progress is
printed at each step or once per minute and saved in `progress.json`. Each run
has a 7200-second and 8-GiB guard; these kill only the runner's solver child.
The final summary excludes unconverged or inequivalent results. Each candidate
must actually reuse fields; iteration/status histories and all 12 Az/mu TIFF
hashes must match the first reference. A difference stops further launches for
review (it is not silently treated as a speed improvement).

Resume pins the harness, engine and power-plan GUID too. Completed results are
reverified; incomplete directories are preserved and require manual review,
not automatic retries. Do not modify the experiment while it is running.
Raw process logs and measurement JSON retain profiling, memory samples and
estimated non-solver CPU load. Peak private memory is not OS pool usage.

## Full-revolution waveform gate

`run_selection_sweep.py` automates the selected mask-6 tangent candidate versus
optimized secant (mask 0), three 12-step pairs in AB/BA/AB order. Priority 4 is
rejected and always OFF. It pins the preserved executable/DLLs/image using the
idle-retest manifest; generated configurations, harness hashes and power-plan
GUID are saved for strict resume validation.

```text
python benchmarks/solver_speed/run_selection_sweep.py --prior-manifest ../bench_results/workspace_idle_retest_20261008_01/manifest.json --output ../bench_results/selected_secant_20261009_01 --run-waveforms --prepare-only
python benchmarks/solver_speed/run_selection_sweep.py --prior-manifest ../bench_results/workspace_idle_retest_20261008_01/manifest.json --output ../bench_results/selected_secant_20261009_01 --run-waveforms --resume
python -m unittest discover -s benchmarks/solver_speed -p test_selection_sweep.py
```

The waveform stage only starts after all timing runs converge with repeatable
within-method histories, >=15% median reduction, shortening in every pair,
and paired peak-memory limits. It runs 248 steps for each method sequentially
and calls the existing comparator below. Expect hours for the full stage;
`progress.json` and launcher output identify the method and current step.
Timeouts are bounded at 600 seconds per configured step, memory at 8 GiB.
Failed/incomplete attempts stop for review and are preserved, never overwritten.
No performance claims are made from unfinished or unconverged runs.

Only eligible, strictly converged candidates advance to 248 steps. Configure
both runs for the same complete revolution before using this command:

```text
python benchmarks/solver_speed/compare_waveforms.py <baseline-result-dir> <trial-result-dir> --points 248 --fundamental 2 --output <new-report.json>
```

The fundamental defaults to bin 2 for the IEEJ-D four-pole full mechanical
revolution. EMF uses identical periodic centered differences, including the
wraparound. There is no phase alignment or amplitude fitting. Flux RMS, EMF
RMS and harmonic limits are checked separately. Missing, nonfinite, incomplete
or unconverged data are **not assessable**, never a pass. Do not apply the
periodic gate to a partial 12-step timing sweep.

## Direct initialization: full revolution and large displacement

`run_initialization_validation.py` follows the completed three-pair direct
initialization ablation. It pins that experiment's executable, DLLs, source
configuration and image, and generates four paired LINEAR/DIRECT tests:

- Full revolution: 248 points, 12 pixels per step (about 1.452 degrees).
- Large displacement: 12 points each at 48, 124 and 248 pixels per step
  (about 5.806, 15 and 30 degrees).

Only step count and displacement change in YAML. Both modes use tangent AMG,
energy line search, mask 6, 12 threads, chunk 1, tolerance 1e-3 and 300 outer
iterations. Anderson and priority-4 field reuse remain OFF. This is not an
angle-prediction experiment and does not change product defaults.

```powershell
.\build_solver_speed\bench_py312\Scripts\python.exe benchmarks/solver_speed/run_initialization_validation.py --exe build_nonlinear_initialization/Release/MagFDMsolver.exe --reference ../bench_results/direct_initialization_20261010_01 --output ../bench_results/direct_validation_20261011_01 --prepare-only
.\build_solver_speed\bench_py312\Scripts\python.exe benchmarks/solver_speed/run_initialization_validation.py --exe build_nonlinear_initialization/Release/MagFDMsolver.exe --reference ../bench_results/direct_initialization_20261010_01 --output ../bench_results/direct_validation_20261011_01 --resume
.\build_solver_speed\bench_py312\Scripts\python.exe -m unittest discover -s benchmarks/solver_speed -p 'test_*.py'
```

Preparation validates inputs and saves the manifest without launching a solver.
Execution is sequential (eight runs for `--suite all`); the full-revolution
pair takes several hours. Use `--suite full` or `--suite large` with separate
new output directories to isolate stages. Resume must use the original suite
and identical scripts, configuration, binary, DLLs, source experiment and
power-plan GUID. Incomplete attempts are retained and stop automatic resume.

Every step must strictly converge with finite residual below 1e-3. The first
step must retain linear initialization; every subsequent DIRECT step must
actually use the eligible previous converged state. Unexpected fallback is
retained for review, not silently counted as successful direct initialization.
All periodic flux/EMF/harmonic gates above apply to the 248-point pair. Large
displacements check same-angle flux NRMS <=0.1%, not sparse-sampled periodic
EMF/harmonics. A failure stops further launches for review. No predictor or
Anderson stage starts automatically.

Time includes output completion. Process memory/CPU samples and estimated
background load are retained; speed is reported only for valid pairs, and a
single pair is not repeated timing evidence. Both runs must stay within 8 GiB;
DIRECT peaks must also be at most twice LINEAR's RSS/private peaks. These
checks do not establish absence of a memory leak or measure OS kernel pools.
Each child has an 8-GiB and 600-seconds-per-configured-step guard; another
running solver or insufficient free disk space prevents launch. Guards never
stop unrelated processes. Follow `progress.json` or launcher output.

Completed on 2026-10-15: all eight runs and 568 steps converged, with all four
quality/memory gates passing. The full-period pair took 10,940.629 / 6,657.868
seconds (39.15% reduction). At 30 degrees per step there was no meaningful
timing gain and outer iterations increased; this gate is not an unconditional
speed/adoption decision. See the [review and archived evidence](../../docs/research/NONLINEAR_INITIALIZATION_EXPERIMENTS.md#completed-full-revolution-and-large-displacement-gate-2026-10-15).
The original evidence directory is complete: do not reuse it for a new trial
or run `--resume` merely to inspect results, since resume rewrites aggregates.

## Angle prediction, then safeguarded Anderson

Use the separate `build_nonlinear_prediction/` build; do not overwrite the
preserved direct-start binary. `run_prediction_pairs.py` compares three 12-step
pairs in AB/BA/AB order. Prediction is fixed beta=1 and residual-gated; AA is a
separate stage with fixed depth=3/beta=.3, not a simultaneous algorithm change.

```powershell
.\build_solver_speed\bench_py312\Scripts\python.exe -m unittest discover -s benchmarks/solver_speed -p 'test_*.py'
.\build_solver_speed\bench_py312\Scripts\python.exe benchmarks/solver_speed/run_prediction_pairs.py --exe build_nonlinear_prediction/Release/MagFDMsolver.exe --reference ../bench_results/direct_initialization_20261010_01 --output ../bench_results/angle_prediction_20261015_01 --stage predictor --prepare-only
.\build_solver_speed\bench_py312\Scripts\python.exe benchmarks/solver_speed/run_prediction_pairs.py --exe build_nonlinear_prediction/Release/MagFDMsolver.exe --reference ../bench_results/direct_initialization_20261010_01 --output ../bench_results/angle_prediction_20261015_01 --stage predictor --resume
```

The directory above completed on 2026-10-15. Review on 2026-10-16 rejected
the predictor: 0/30 candidates accepted, unchanged convergence histories and
fields. Its raw time difference is not credited as a predictor speedup.
Inspect the archived results; do not resume/reaggregate a completed experiment.
Use a new output directory for
fresh experiments. To resume use identical pinned binary/DLL/input/harness/power
plan; incomplete attempts stop for review and are never automatically overwritten.

The selected initializer is DIRECT. Start the independent AA stage with
`--stage anderson --initializer direct --predictor-reference
../bench_results/angle_prediction_20261015_01` and a **new** output directory,
first with `--prepare-only`, then `--resume`. A completed passing predictor stage
with the same binary is mandatory. No next stage is launched automatically.

Both stages require strict convergence, repeatable within-mode histories and
fields, unchanged archived OFF/control results, aligned flux RMS <=0.1%, actual
initializer/AA use and paired memory limits. Background CPU load is retained.
Total time includes prediction probes and output drain. These 12 points do not
validate periodic EMF/harmonics. See the [research report](../../docs/research/NONLINEAR_INITIALIZATION_EXPERIMENTS.md)
for supported motion, safeguards and remaining full-revolution gates.
