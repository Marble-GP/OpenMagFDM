# OpenMagFDM Voxel Lab — ブラウザー描画の検証画面

STEP表示、任意粒度でのボクセル生成、マウスによる回転/拡大縮小、
粒度ごとの連続計測を行うローカルHTML/JSツール。
既存WebUIとは別ポートで動く。3D磁界ソルバーはまだ呼び出さない。

## 起動

この作業環境ではC++実行ファイルとJS依存を準備済み。
リポジトリ直下（`OpenMagFDM`）のPowerShellから：

```powershell
.\tools\voxelizer\lab.ps1
```

ブラウザーで **http://127.0.0.1:8766/** を開く。サーバーを動かしているコンソールは開いたままにし、
終了時はCtrl+Cを押す。使用中のポートと重なる場合は`--port 8767`などを渡す。

入口のHTMLは[`dist/index.html`](dist/index.html)。C++プログラムを呼ぶため、
HTMLをダブルクリックして`file://`で開く方法では動かない。
このPC内のHTTPサーバー経由で使用する。外部サイトへのアップロードやCDN読込はしない。

## 操作の流れ

1. 「サンプル：7部品のローター」、または自分のSTEP/STPを選ぶ。
2. 「ボクセル辺長」にmm単位のサイズ、「周囲の空気」に片側の希望厚さを入力する。
3. 「この粒度でボクセル生成」を押す。C++変換後、JSで描画用メッシュを作る。
4. マウスの左ドラッグで回転、ホイールで拡大縮小、右ドラッグで移動する。
5. 表示対象をSTEP / ボクセル / 重ね表示から選ぶ。空気、透明度、ワイヤー、解像度も変更できる。
6. 「現在の表示を計測」、または辺長リストを指定して「連続生成・計測」を押す。
7. 結果は表へ追加される。比較が終わったらCSVを書き出す。

辺長は**小さいほど細かい**。既定リスト`2, 1, 0.5, 0.25`は粗い→細かい順。
「順序を反転」で細かい→粗い順にできる。同じ粒度をリストに繰り返し書くこともできる。
連続測定時にSTEP単独表示が選ばれていた場合は、ボクセル表示へ切り替える。

同じ入力形状を比較できるよう、材料情報は各生成結果のVTIとmanifestへ保存する。
サンプルは3材料ID、自分のSTEPは既定でソリッドごとに別材料IDになる。
CAD側の色/材料物性の自動読込や、画面上での材料対応編集はまだない。

ボクセル生成は既存の`MagVoxelizer`による**元BRepソリッドのセル中心判定**。
STEP表示用の三角形メッシュからボクセルを切っているわけではない。
表示用近似の許容偏差は0.05 mm、角度偏差は0.35 radで固定し、粒度比較中に変えない。

## 二つの描画方式

| 方式 | 描画するもの | 調べられる負荷 |
|---|---|---|
| 表面抽出 | 材料が異なる隣接セル間と領域外周の面 | 通常の表面表示に近い負荷 |
| 全セル / InstancedMesh | 各セルの立方体。内部面も含む | 内部を省略しない表示の負荷 |

両方式とも同じ材料ID配列を使う。表面抽出は同じ材料内の面を省略し、
材料間の内部界面は保持する。画面の描画方式変更時はVTIを作り直さずJSメッシュだけ作り直す。
表示が上限等で失敗した場合は、再生成してから改めて比較する。

空気はVTI内で常にID 0として保持される。「空気も描画」は表示対象への追加だけを制御する。
不透明度0は完全透明、1は不透明。部品の不透明度は全部品共通。
半透明の重なりや、全セルインスタンス内部の前後ソートは近似であり、
透明表示の見え方を物理的な密度や占有率として解釈しない。

## 計測条件と結果

毎回同じモデル領域にカメラを合わせ、1秒ウォームアップ後、約3秒自動回転する。
測定終了をまたぐフレーム間隔も集計し、最後の重いフレームを落とさない。
実際に集計した間隔の合計はCSVの`measuredIntervalMs`に入る。
計測中は条件操作を無効化し、マウスによるカメラ変更も止める。
タブ非表示・リサイズ・WebGL喪失・ユーザー停止は無効理由を記録する。
生成/表示の上限超過も失敗行として残し、連続測定を終了する。

| 指標 | 意味と制限 |
|---|---|
| C++生成 ms | 子プロセスの起動から終了まで。STEP再読込、分類、VTI/manifest書込を含む |
| 転送 ms | ローカルHTTPで材料ID配列を取得する時間。CSVに記録 |
| JSメッシュ ms | Worker内の表面/インスタンス配列作成時間 |
| meshSetupMs | メインスレッドでThree.jsオブジェクトを構築する時間 |
| firstRenderCpuMs | 初回render呼出しのCPU時間。GPU完了待ち時間ではない |
| FPS / フレームp95 | requestAnimationFrameの実際の間隔。ディスプレイの更新周期で頭打ちになる |
| CPU ms | renderer.render()呼出しの中央値。ブラウザー全体のCPU使用率ではない |
| GPU ms | EXT_disjoint_timer_query_webgl2対応時のみ。非同期に取得する。未対応/無効は空欄 |
| 三角形 / Draw calls | 実際に表示したフレームのThree.jsカウンター |
| JSヒープ | performance.memory対応時のみ。プロセス全体やOSの使用メモリではない |
| 属性バッファbytes | 配列サイズから計算した目安。実VRAM使用量ではない |
| longTasks | 対応ブラウザーで観測した長時間タスク。未対応は空欄 |

CSVには入力STEPのSHA-256、粒度、格子数、実原点/間隔、空気の有無、透明度、
描画方式、DPR、キャンバスサイズ、カメラ、ブラウザー、取得できたWebGLレンダラー情報も記録する。
モデル名は比較用の識別子として使い、物理精度の保証にしない。

比較時にはDPR・キャンバスサイズ・空気・透明度・描画方式を揃える。
粗い→細かいだけでなく逆順でも繰り返し、起動直後、他の負荷、ブラウザーのGC等の影響を見る。
1回の数値だけで一般的な性能差としない。

「周囲の空気」はmmで固定し、C++へは`ceil(希望厚さ / 辺長)`のpaddingセル数として渡す。
希望厚さが辺長で割り切れなければ実際の厚さが少し増える。
CSVの原点/格子数も照合する。既定例の2 mm空気と2/1/0.5/0.25 mm粒度は割り切れる。

## 生成ファイルと制限

- セッションごとに`build_voxelizer/browserlab/run_<ID>/`を作る。
  各入力STEP、プレビュー、C++ログ、生成VTI/manifestを別ディレクトリに保存する。
- 「VTIを保存」「条件JSON」から対応する結果を取得できる。
  旧ディレクトリは上書きしない。セッション終了後もディスクに残る。
- HTMLの測定履歴はタブ内のメモリにある。閉じる前にCSVを書き出す。
- STEP最大50 MiB、最大64ソリッド、格子500万セル。
  表示は150万面または75万インスタンスまで。粒度は0.001〜1000 mm。
- 同時ネイティブ処理は1件、1件180秒まで。停止ボタンはこのジョブが起動したプロセスのみ停止する。
- 1セッション64ジョブ、出力総量1 GiB超で新規ジョブを拒否する。
  実行中ジョブの増分はこのディスク容量の事前判定には含まれない。
- 旧Three.jsのgeometry/material/instance buffersとWorkerを解放してから次を表示する。
  CADとボクセルの両表示に必要な資源は保持する。
- バックエンドは127.0.0.1のみ。Host/Origin/ローカルトークンを確認し、任意パスやシェルは受け付けない。
  既存WebUIの認証基盤や他ユーザー向け共有サーバーではない。

## 新しい環境で準備する場合

C++/OCCTの準備は[親README](../README.md)を参照。
HTML側にはNode.jsとnpmを使って固定版Three.jsのローカル配布物を用意する。

```powershell
# OpenMagFDM直下。MagCadPreviewもこのビルドに含まれる
cmake --build build_voxelizer --config Release --parallel 4
cd tools/voxelizer/browserlab
npm ci --ignore-scripts --no-audit --no-fund
npm run vendor
```

`dist/vendor/`は生成物でGit対象外。Three.js本体・OrbitControls・MITライセンスをコピーする。
実行時のCDN通信は不要。サーバー本体はPython標準ライブラリだけを使い、VTKは不要。
Windows用`lab.ps1`は今回の独立Python/OCCT環境を参照する。
他環境ではライブラリ検索パスを設定し、
`python server.py --native <C++実行ファイルのディレクトリ>`で起動できる。
今回のビルド/実行確認はWindowsのみ。
